# Everdune AI Production Rules

1. Read PROJECT.md and TODO.md before editing.
2. Reuse existing systems before inventing new ones.
3. Prefer data-driven content.
4. Keep assets semantically named and catalogued.
5. Never introduce contradictory lore.
6. Never replace canonical art with generic substitutes.
7. Keep single-player state concerns separate from future multiplayer concerns.
8. Every feature must improve the player loop.
9. Every system needs deterministic verification where practical.
10. Preserve future extensibility without rewriting the foundation.
11. Treat temporary work as explicit placeholder debt.
12. Never use breadth to hide unresolved P0 quality gaps.
13. main.gd is orchestration, not a content database.
14. Retire obsolete implementations rather than keeping parallel authorities.
15. Asset manifest drift is a CI failure.
16. Save migration and round-trip checks are required for persistence changes.
17. Update TODO.md in the same change when task state changes.
18. One coherent task per PR.
19. Do not expand beyond the active milestone without updating PROJECT.md and TODO.md.
20. AI speed is valuable only when validated progress increases.
